## Experiments

### A — model-conditioned pose

Question: given the correct model identity, how well does each method estimate
the pose of that object in the same RGB-D frame?

- Geometry receives the full depth scene, intrinsics, and the selected CAD
  model; it must generate its own candidates and must not receive GT masks,
  poses, boxes, or locations.
- A future learned path may receive only the inputs supported by its actual
  interface, such as RGB, depth/intrinsics, model identity or text prompt,
  and masks generated by its own detector/segmenter. GT masks, boxes, poses,
  and locations are forbidden.
- Both outputs must be normalized to `T_camera_object`, object/model frame to
  camera frame, with metres internally. BOP CSV output may convert translation
  to millimetres only at the serialization boundary.

### B — end-to-end detection plus pose

Not run and not currently valid. It requires both methods to discover/select
instances without the manifest-provided object identity. The current geometry
branch has not demonstrated reliable catalogue-wide model selection, so no
end-to-end winner or benchmark claim is manufactured.

## Geometry configuration

Use the frozen production baseline in
`experiments/geometry_baseline_summary_v1.json`: CAD representation, standard
Open3D voxel/normal/FPFH/RANSAC/point-to-plane ICP, geometry candidates,
support-plane removal, observed normals toward the camera, bidirectional
verification, seed 7, and the documented fixed thresholds. Do not switch to
PPF, reconstructed models, or a diagnostic variant for this comparison.

## Learned configuration requirement

A future run must record the exact existing learned wrapper, model/config paths,
checkpoint hashes and sizes, prompt/model identity, RGB-D preprocessing,
intrinsics handling, device, warm/cold timing, and pose output conversion. It
must use the pipeline's normal mask/initialization path, never GT assistance.
No new wrapper, model, or checkpoint may be silently introduced under this
protocol.

## Metrics and failure taxonomy

Evaluate GT only after prediction. Use the existing official BOP integration
where valid: MSSD, MSPD, RE, and TE with symmetry handling; naive rotation is
descriptive only. Also record translation error, pose availability, accepted
or rejected status, and stage-specific failure.

Geometry failures are classified as candidate isolation, global
correspondence/registration, refinement divergence, geometric false positive,
or verification rejection. Learned failures are classified as dependency or
checkpoint unavailable, detector miss, wrong class/object, segmentation
failure, pose initialization failure, pose failure, or output/units/frame
conversion failure.

Runtime is split into one-time model loading and steady-state per-frame work.
For geometry record preprocessing, candidate generation, registration, and
verification when available. CPU/GPU and memory/resource differences must be
reported; no overall winner is declared from unequal hardware or information
assumptions.
